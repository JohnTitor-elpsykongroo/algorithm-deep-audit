# 报告结构与终检

在交付阶段使用。可按研究问题调整篇幅、合并章节，但保留以下信息；不适用项解释原因，缺证据项显式留为未知。

## 1. 研究边界与结论摘要

- 仓库根目录、版本/提交、已有工作树差异、分析日期；研究问题、输入/输出、代表性调用及有效配置。
- 结论的适用范围、最重要的发现及其证据 ID；完整审计或阶段性报告及原因。
- 静态阅读、本次运行、已有日志、外部资料各自的使用范围；排除项、联网限制和材料缺口。

| 阶段 | 检查结果 | 已覆盖对象/证据 | 未决项与影响 | 下一步 |
|---|---|---|---|---|
| G1 边界 | 通过/部分/受阻 | | | |
| G2 路径 | 通过/部分/受阻 | | | |
| G3 数学 | 通过/部分/受阻 | | | |
| G4 反证 | 通过/部分/受阻 | | | |
| G5 竞争研究 | 通过/部分/受阻 | | | |

阶段表是汇总；仍须保留模块/配置/分支层面的覆盖表。不要把“读过文件”或无依据的覆盖百分比当成通过条件。

## 2. 源码证据与主张账本

| ID | 关键结论 | 类型 | 文件路径、函数/符号、行号或外部精确出处 | 生效配置/路径 | 支撑内容 | 反证/局限 |
|---|---|---|---|---|---|---|

类型使用源码事实、论文描述、文档描述、推测/推导或运行观察。源码证据表必须能独立定位关键实现，论文证据不能代填源码定位。引用函数中与结论相关的窄行段；组合推导列出多个证据 ID。大表可放附录，摘要链接到条目。

## 3. 执行流程与分支

给出代表性调用 → 有效配置/分派 → 预处理 → 数据结构 → 算法/优化 → 后处理 → 输出/指标的流程，可用表、伪代码或图。标出关键数据形状、状态变化、条件分支、异常/回退及外部边界。静态追踪的路径标为“按该调用静态解析”，不写成已观测轨迹。

## 4. 数学解析与论文对照

包含符号—代码映射、目标/规则、约束、初始化/更新、参数来源、停止/失败、数值处理及相应证据 ID。只对有依据的内容讨论复杂度与保证。

| 议题 | 论文/文档描述及出处 | 源码行为及证据 | 是否一致 | 对结果的影响/待核实条件 |
|---|---|---|---|---|

## 5. 反证、测试与未知问题

| 被挑战主张 | 能推翻它的情形 | 实际检查位置/证据 | 检查结果及修订 | 测试断言/缺口 |
|---|---|---|---|---|

| 未知问题 | 已检查范围 | 缺失证据 | 影响哪些结论 | 最小解决动作及授权/资源需求 |
|---|---|---|---|---|

区分“测试代码包含断言”“已有日志报告通过”和“本次实际通过”。将未执行测试、不可见依赖实现、尚未验证的数学假设等明确列出。

## 6. 候选技术路线与实验建议

使用研究参考中的候选比较和最小实验卡。给出基于证据的优先级、暂不采用路线及理由；说明哪个实验最先执行能减少哪项关键不确定性。不能只有论文名单或笼统的“换个模型试试”。

## 交付前终检

- 每个关键结论有可核验定位与适用条件；事实、论文/文档、推导和运行结果没有混写。
- 调用、配置优先级和实际分派相互一致；未遗漏会改变结论的后处理、异常或替代路径。
- 数学解析能对应源码中的有效行为，重要差异与未证明性质没有被掩盖。
- G1–G5 有真实检查记录；有核心缺口时标记阶段性结果，不声称完整。
- 推荐路线已说明可比条件和限制，每个有价值候选都有最小可证伪实验。
- 仓库保持在授权范围内；未经授权未修改代码、运行训练或把实验计划写成已执行结果。
