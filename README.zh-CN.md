# Algorithm Deep Audit

[English](README.md) | **简体中文**

面向已有算法项目的研究级分析 Codex Skill。沿源码追踪实际行为，重建数学模型，主动寻找反证，并通过可证伪的实验方案比较竞争技术路线。

## 适用场景

- 跨配置、预处理、求解器、后处理和异常分支理解算法。
- 核对实现是否符合论文及文档中的假设。
- 分析数值行为、停止条件、动态分发及测试覆盖缺口。
- 在投入开发或训练前评估替代技术路线。

本仓库提供 Codex 使用的指令和参考模板，不是可直接运行的分析程序或训练框架。

## 开始使用

将仓库克隆到你选择的目录：

```sh
git clone https://github.com/JohnTitor-elpsykongroo/algorithm-deep-audit.git
```

Skill 入口为 [SKILL.md](SKILL.md)，请保留同目录下的 `agents/` 和 `references/`。在 Codex 中提供本地 `SKILL.md` 路径及待分析的项目路径。如果当前会话的 Skill 选择器中已能找到它，可使用 `$algorithm-deep-audit` 调用。

例如，克隆到 `D:\WorkSpace\skills` 后：

```text
请使用 D:\WorkSpace\skills\algorithm-deep-audit\SKILL.md 中的 Skill，
分析 D:\WorkSpace\my-algorithm。

以 `python main.py --config configs/eval.yaml` 为代表性调用，
但不要执行该命令。重点检查有效配置、目标函数、求解器更新、
数值处理和回退路径。联网权限允许时比较竞争技术路线。
保持只读，不运行测试，不启动训练。
```

将示例路径和命令替换为你的实际项目入口。提供相关论文、配置和研究问题有助于确定分析边界。仅克隆到任意目录不代表 Codex 会自动发现该 Skill。

## 审计流程

每个阶段都设置覆盖与证据检查。找到核心入口只是分析的起点。

| 阶段 | 工作内容 | 检查要求 |
| --- | --- | --- |
| G1 — 研究边界 | 盘点仓库、版本、依赖、配置、测试、论文和入口。 | 明确研究范围、代表性调用及覆盖计划。 |
| G2 — 执行路径 | 追踪预处理、数据结构、算法分发、优化、后处理和异常。 | 从输入到输出形成闭合路径，核对重要分支及外部边界。 |
| G3 — 数学模型 | 重建目标或规则、约束、更新、参数、停止条件及数值处理。 | 将数学解释映射到源码证据，揭示论文与实现的差异。 |
| G4 — 主动反证 | 挑战重要结论，检查配置覆盖、隐藏替代路径及测试断言。 | 修订被推翻的结论，记录未决冲突和覆盖缺口。 |
| G5 — 竞争路线 | 检索竞争论文和开源算法，涵盖不同机制及有意义的简单基线。 | 比较假设与适用条件，为每个有价值的候选提出最小实验。 |

围绕研究问题和重要路径选择性阅读，不用打开文件的数量衡量覆盖率。核心路径或数学模型仍有未决冲突时，应交付阶段性报告，不能声称已完成完整审计。

## 证据标准

明确区分以下内容：

- **源码事实**：文件路径、函数或符号、行号，以及生效配置。
- **论文描述**：原始来源、版本、页码、章节或公式。
- **文档描述**：README 和注释中的表述，与实现证据分开。
- **推测与推导**：明确前提、支撑证据及证伪条件。
- **运行观察**：记录命令、环境、数据及结果来源；不把静态分析写成已执行的测试。

整个审计过程持续维护覆盖表、证据账本、未知与反证清单。

## 交付内容

最终报告包括研究边界与阶段覆盖、源码证据表、执行流程、数学解析、论文与实现差异、反证发现、测试缺口、未知问题、候选技术路线和实验建议。

每个有价值的替代方案都需提供最小实验计划，包含假说、干预点、基线、数据、指标、公平资源预算、预期风险及淘汰条件。实验方案不等于实验结果。

## 执行边界

**默认只读。** 本 Skill 不授权修改代码、配置、数据或环境，不授权安装依赖、运行仓库入口或测试、启动训练。执行操作需要明确授权，且应限制在约定范围内。

工具与网络权限允许时开展外部研究。离线时继续本地分析，明确标注待核实候选和检索限制。不会为检索而上传私有源码、数据或敏感配置。

默认在对话中提交报告。用户要求保存时，使用指定位置或受审计源码树之外的审计目录。
